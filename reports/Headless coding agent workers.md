# Pi leads, OpenCode follows, Goose trails headless

**Pi is the best fit of the three as an unattended worker under an external supervisor.** Its long-lived JSONL RPC mode lets a supervisor steer, abort, compact and poll cost mid-run. It has the most detailed per-server compatibility controls for vLLM, SGLang and llama.cpp, and its default prompt is under 1,000 tokens. Both Gas Town and Gas City already ship Pi presets. **OpenCode V2 (2.2.5) is a strong second.** Its non-interactive `run` cannot hang on a permission prompt and it has a 2-minute default shell timeout. But V2 broke the V1 plugin and permission mechanisms that the Gas Town and Gas City OpenCode presets depend on, and it no longer has LSP feedback at all. **Goose (1.57.0) is usable but third.** It has good turn and timeout caps, but its edit tooling is thin, it has open bugs that corrupt edits and hurt local models, it is a 208 MB binary, and no orchestrator preset exists for it. The earlier chat assessment was wrong on all three headline claims, as corrected below. Among the alternatives, **mini-swe-agent** is the most robust control for flaky tool-call parsers, and **Qwen Code** fits naturally if you run Qwen models. **Codex CLI** is a top harness, but it speaks only the Responses API, so it needs a proxy in front of self-hosted servers. Droid, Crush and Aider are poor fits. One caution runs through everything: with 32B to 70B open-weight models, the serving layer (tool-call parser, chat template, reasoning parser) causes more failures than the harness does, so pin the inference server, parser and template as one unit and verify them first.

## The earlier assessment got all three headline claims wrong

The prior chat summary made three claims, and the notes contradict each one. The corrections matter, because each claim pointed toward a different integration decision.

The four default tool schemas add an estimated 400 to 500 tokens, so the total is about 1,000 tokens ([system-prompt.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/system-prompt.ts); consistent with [eesel.ai](https://www.eesel.ai/blog/pi-coding-agent)'s "under 1,000 tokens") | Still the leanest of the three, but about twice the claimed size |

The edit and write tools carry a "TODO: Add LSP notification and diagnostics" ([edit.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/tool/plugin/edit.ts)) | The supervisor or worker instructions must run typecheck and lint explicitly |

Pi now has built-in MCP, codemode and tool search, added in v0.99.0 ([CHANGELOG](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). Its npm package is now `@earendil-works/pi-coding-agent`, not `@mariozechner/...`. OpenCode V2 no longer has the qwen.txt and beast.txt prompts, `permission.bash`, `OPENCODE_PERMISSION` or V1 plugins. Goose no longer has the `goosed` REST server, the `text_editor` tool, Morph/Relace fast-apply or lead/worker multi-model mode ([cli.rs](https://github.com/aaif-goose/goose/blob/main/crates/goose-cli/src/cli.rs), [multi-model docs](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/multi-model/index.mdx)).

## Pi exposes the richest control plane but trusts the operator completely

Pi offers four integration modes: print (`-p`), a one-shot JSONL stream (`--mode json`), a long-lived bidirectional JSONL RPC over stdio (`--mode rpc`), and an in-process TypeScript SDK ([cli-integration.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/cli-integration.md)). **RPC mode suits a supervisor best.** Its commands include `steer`, `follow_up`, `abort`, `compact`, `set_model`, `fork` and `get_session_stats`; the last returns tokens, cost and context-window usage ([rpc-commands.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc-commands.md)). The event stream carries per-message cumulative usage and cost, tool start/end events with `durationMs`, retry events and compaction events. Since v1.5.0 it also separates billed cost from catalog-estimated cost (`totalFromProvider`). A supervisor has to handle three details correctly. First, completion is signalled by `agent_settled`, not `agent_end`, because retries or compaction can follow `agent_end`. Second, **in JSON mode a failed or aborted response does not set a nonzero exit code**, so the supervisor must parse `stopReason`. Third, the reader must drain stdout continuously, or Pi stalls on backpressure, and must not use Node's `readline`, which splits on U+2028 ([json.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/json.md)).

For unattended runs, Pi's weakness is that it assumes the operator provides every guardrail. It "does not ask for approval before every tool call," ships no sandbox, and treats the lack of one as outside its security boundary ([security.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/security.md)). **The bash tool has no default timeout** ([bash.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/bash.ts)), and the CLI has no turn or step cap. The supervisor must therefore enforce wall-clock, token and cost limits itself through `abort`. The extension system makes this practical. A `tool_call` hook can block or rewrite any call, including injecting a default `timeout`. The shipped examples include `permission-gate.ts`, `protected-paths.ts` and `git-checkpoint.ts` ([extensions.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)). Headless modes skip untrusted project extensions and settings unless `--approve` is passed. That is a safe default, but AGENTS.md and CLAUDE.md load regardless, so prompt-injection exposure remains.

**Pi has the most detailed open-weight provider controls of the three.** OpenRouter is built in, with routing preferences and session-affinity headers. Self-hosted servers are configured in `models.json` with `api: "openai-completions"` and a `compat` block covering several areas ([models-configuration.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models-configuration.md)). Reasoning control includes `thinkingFormat` (`qwen-chat-template`, `deepseek`, `zai` and others) and per-server thinking-budget field names (`thinking_token_budget` for vLLM, `thinking_budget` for SGLang, `thinking_budget_tokens` for llama.cpp). Message-ordering quirks include `requiresReasoningContentOnAssistantMessages` and `requiresAssistantAfterToolResult`. There are also `vllmPriority` and `supportsFinishReason`. llama.cpp is a first-class integration with router management ([llama-cpp.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/llama-cpp.md)). Two caveats apply. Auto-detection keys off the URL, so endpoints on a bare IP need explicit `compat`. And llama.cpp Responses streams that omit `output_index` now fail with an error, so use `openai-completions` for llama.cpp. The edit tool takes an array of exact, unique, non-overlapping `oldText`/`newText` pairs. Its fuzzy fallback normalizes only Unicode, trailing whitespace and smart quotes, not indentation ([edit-diff.ts](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/tools/edit-diff.ts)). Since v1.5.0, tool arguments are type-coerced, so stringified numbers no longer fail validation ([CHANGELOG 1.5.0](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/CHANGELOG.md)). This helps sloppy 32B models. The nested `edits` array may still trip weak tool-callers, but the legacy single-pair form is still accepted.

On context and maintenance, Pi's defaults need tuning for small windows. Auto-compaction triggers at the window minus 16,384 tokens and keeps 20,000 recent tokens ([settings.md](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/settings.md)). On a 32K local window, that 36K combined budget does not fit, so set `compaction.modelOverrides`. The project moves very fast. Version 1.0 shipped on 2026-10-01 and seven releases reached 1.5.0 by 2026-11-02, with breaking changes inside minor versions. It is MIT-licensed and now owned by Earendil, with Mario Zechner still the dominant committer. **Both Gas Town and Gas City ship Pi presets** using extension hooks, but both drive Pi's TUI through tmux with an 8-second readiness delay rather than using RPC. Gas Town's preset declares no resume support ([gastown agents.go](https://github.com/gastownhall/gastown/blob/main/internal/config/agents.go), [gascity profiles.go](https://github.com/gastownhall/gascity/blob/main/internal/worker/builtin/profiles.go)). One data point counts against Pi. On the goose team's self-reported Terminal-Bench 2 runs with Sonnet 4.6, Pi scored **47.2%**, against 52.8% for OpenCode and 50.6% for stock goose ([Harbor README](https://github.com/aaif-goose/goose/blob/main/evals/harbor/README.md)). That is a frontier-model result from a competitor's team and says little about 32B to 70B models, but it argues for a bake-off rather than an assumption.

## OpenCode V2 is headless-safe but silently breaks existing orchestrator presets

OpenCode's V2 rewrite, released around September 2026 and now at 2.2.5, created a sound headless design. `opencode run --format json` emits NDJSON events and exits 1 on error and 130 on interrupt. `--standalone` gives each worker a private server instead of the default shared per-user background service. `opencode serve` exposes an OpenAPI-described API used through `@opencode/client`, and `opencode acp` is implemented in full ([commands.ts](https://github.com/anomalyco/opencode/blob/dev/packages/cli/src/commands/commands.ts), [noninteractive.ts](https://github.com/anomalyco/opencode/blob/dev/packages/cli/src/run/noninteractive.ts)). **Non-interactive `run` never hangs on a prompt.** Without `--auto`, every permission request is auto-rejected with the model-visible message "Continue without this action". `question` forms are cancelled with "make reasonable assumptions". With `--auto`, requests are approved once. Shell commands default to a **2-minute foreground timeout**, and glob and grep searches to 30 s ([tools.mdx](https://github.com/anomalyco/opencode/blob/dev/services/www/src/docs/content/tools.mdx)). A custom driver over `serve` does not get this behavior and must answer `permission.asked` events itself.

**The permission model has one trap for worktree isolation.** Rules are an ordered list of `{action, resource, effect}` entries where the last match wins, and unmatched requests default to `ask`. **V2 allows `external_directory` by default**, whereas V1 asked ([permissions.mdx](https://github.com/anomalyco/opencode/blob/dev/services/www/src/docs/content/permissions.mdx), [migrate-v1.mdx](https://github.com/anomalyco/opencode/blob/dev/services/www/src/docs/content/migrate-v1.mdx)). With `--auto` alone, a worker can therefore write into sibling worktrees. Deny `external_directory` explicitly, along with `git push *` and `question`. Inject the rules through `OPENCODE_CONFIG_CONTENT`. **`OPENCODE_PERMISSION` has zero references in V2 source.** That matters because Gas City's OpenCode profile sets `OPENCODE_PERMISSION={"*":"allow"}` and drives the TUI with `--prompt` ([gascity profiles.go](https://github.com/gastownhall/gascity/blob/main/internal/worker/builtin/profiles.go)). Gas Town installs a V1 JS plugin that injects `gt prime` context through `experimental.chat.system.transform` ([gastown.js](https://github.com/gastownhall/gastown/blob/main/internal/hooks/templates/opencode/gastown.js)), and "V1 plugin implementations do not run in V2." The likely result under V2 is a TUI worker with no priming that stalls on the first `ask`. Nobody has tested this directly; a single `OPENCODE_PERMISSION='{"*":"allow"}' opencode run "touch x"` on 2.2.5 would settle it. Either way, either pin 1.x for the stock presets or move to `run --standalone --auto --format json` or ACP. V2 also discovers only `AGENTS.md`, dropping the CLAUDE.md fallback, and stores sessions in a database (`OPENCODE_DB`). Gas City's transcript reader, which reads session files, should be re-verified against that.

For open-weight models, V2 is lean but loses some guidance. The generic system prompt is 756 bytes. Model-specific prompts exist only for GPT, Claude, Kimi, Trinity and Meta, so Qwen, GLM and DeepSeek get the generic prompt ([optimize.ts](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/plugin/optimize.ts)). Matching is by model-ID substring, so "gpt-oss" probably routes to `gpt.txt` and the `patch` tool. This is an unverified inference worth testing. The `edit` tool does exact-once matching with Unicode, whitespace and line-trim normalization, and 2.2.5 added model-robustness fixes: a `bash` call is aliased to `shell`, a failed edit shows the closest lines, and a missed read names the nearest existing folder ([CHANGELOG](https://github.com/anomalyco/opencode/blob/dev/CHANGELOG.md)). MCP and plugin tools default into **Code Mode**, where they are reached by JavaScript through an `execute` tool. That is a risk for 32B models, and denying `execute` removes it. Providers are AI SDK packages (`aisdk:@ai-sdk/openai-compatible`) backed by a bundled models.dev catalogue. Local deployments are not in that catalogue, so set `capabilities.tools` and the context limit yourself. Compaction keeps about 15K recent tokens, and V1's tool-output pruning is gone. Per-step snapshots go to a separate internal git object store and leave the worktree index alone ([snapshots.mdx](https://github.com/anomalyco/opencode/blob/dev/services/www/src/docs/content/snapshots.mdx)), but they scan the directory each step, so set `snapshots: false` when the supervisor owns git. The project ships releases almost daily (2.0.26 to 2.2.5 between Oct 8 and Oct 30). It has about 224K stars and 2.4K open issues ([repo](https://github.com/anomalyco/opencode)), plus a V1 history of multi-GB Bun memory growth ([#11399](https://github.com/anomalyco/opencode/issues/11399), [#17237](https://github.com/anomalyco/opencode/issues/17237)). V2 removed the LSP runtime, which caused orphaned-process leaks, but nobody has measured V2 memory.

## Goose bounds runs well but edits and local models are its weak spots

Goose has the best built-in run limits of the three. **`GOOSE_MODE` defaults to `auto`**, `--max-turns` defaults to 1000, `--max-tool-repetitions` caps repeated identical calls, and the shell tool falls back to a **300 s timeout** ([goose_mode.rs](https://github.com/aaif-goose/goose/blob/main/crates/goose-provider-types/src/goose_mode.rs), [shell.rs](https://github.com/aaif-goose/goose/blob/main/crates/goose/src/agents/platform_extensions/developer/shell.rs)). The headless surface is `goose run` with `--no-session`, `--no-profile`, `--with-builtin developer` and `--output-format stream-json`. Its event set is small: `message`, `notification`, `error`, and `complete` with tokens and `cost_usd` ([session/mod.rs](https://github.com/aaif-goose/goose/blob/main/crates/goose-cli/src/session/mod.rs)). There is no explicit outcome reason beyond `metadata.status`, and exit codes were not traced. `goose acp` and `goose serve` (ACP over HTTP/WebSocket) replaced the old REST server. Open Plugins-style hooks (`PreToolUse` deny, `AfterFileEdit`, `Stop`) let a supervisor drop policy into `.agents/plugins/` ([hooks.md](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/context-engineering/hooks.md)).

The weaknesses sit where coding workers spend their time. The developer extension is now just `shell`, `write`, `edit` (exact, unique `before`/`after`, no fuzzy match), `tree` and `read_image`. **There is no file-read tool**, so the model reads files with `cat` or `sed` through the shell, which costs extra tokens on small-context models ([developer/mod.rs](https://github.com/aaif-goose/goose/blob/main/crates/goose/src/agents/platform_extensions/developer/mod.rs)). Open bug **#12884 strips XML-like `</>` tokens from write/edit arguments**, which would corrupt HTML, JSX and generic-heavy code. Open ACP issues report that shell is always delegated to the client terminal, bypassing sandboxes (#12513), and that cancel does not interrupt the agent (#10619). The scheduler is unusable for unattended recipes (#11164). Several Ollama and reasoning-control bugs are open, including #13090 (stall timeout aborts long tool calls) ([issues](https://github.com/aaif-goose/goose/issues?q=is%3Aissue+ollama+tool+calls)). Goose's own documentation says "most locally-hosted models… will need the shim", an experimental second model hop ([tool-shim.md](https://github.com/aaif-goose/goose/blob/main/documentation/docs/guides/tool-shim.md)). With vLLM or SGLang tool parsers enabled, skip the shim. Goose's own Harbor run with a 30B-A3B open model solved **1.1%** of Terminal-Bench 2 ([Harbor README](https://github.com/aaif-goose/goose/blob/main/evals/harbor/README.md)). With Sonnet 4.6, though, its code-mode configuration reached 57.3%, the best harness result in that table, so the harness itself is competitive with a strong model. Goose is Apache-2.0, governed by the Linux Foundation's AAIF and released weekly. **Neither Gas Town nor Gas City has a goose preset.** Integration would go through Gas City's ACP runtime (`acp_command=goose`) ([launch_command.go](https://github.com/gastownhall/gascity/blob/main/internal/config/launch_command.go)), which is exactly the path the open ACP bugs affect.

## Alternatives: one serious contender and one essential control

**Codex CLI** is the strongest open alternative on harness quality. It is Apache-2.0 and written in Rust, with `codex exec --json`, an OS-level sandbox and an official Gas Town preset. With GPT-5.5 it sits at 82.2% on a Snorkel Terminal-Bench 2.0 snapshot ([Snorkel](https://snorkel.ai/leaderboard/terminal-bench-2-0/)). But **Chat Completions support (`wire_api = "chat"`) was removed in early 2026, and only the Responses API remains** ([Discussion #7782](https://github.com/openai/codex/discussions/7782), [DEV](https://dev.to/creeta/codex-cli-dropped-chat-wire-opencodex-picks-up-the-routing-2emb)). OpenRouter supports Responses ([OpenRouter tutorial](https://openrouter.ai/blog/tutorials/codex-cli-openrouter/)). Self-hosted vLLM, SGLang and llama.cpp backends need a translating proxy such as [codex-proxy](https://github.com/lininn/codex-proxy), or a Responses endpoint whose streaming tool calls are less proven. That makes Codex the harness most exposed to serving-layer gaps, and its GPT-tuned `apply_patch` format will probably produce more malformed patches with 32B models; no measurements of that exist. **Qwen Code**, a Gemini CLI fork, speaks OpenAI-compatible APIs natively, with `--output-format stream-json` and a bidirectional `--input-format stream-json` ([headless docs](https://qwenlm.github.io/qwen-code-docs/en/features/headless)). However, the Qwen3-Coder-Next tech report has its own CLI scoring **25.8** on TB2, against 36.2 for the minimal Terminus-2 JSON harness and 30.9 for Claude Code with the same model ([arXiv 2603.00729](https://arxiv.org/html/2603.00729v1)). So matching the vendor's harness to the vendor's model buys nothing.

**mini-swe-agent** belongs in every bake-off. Its agent is about 100 lines of Python, its only tool is bash, and it **does not use the tool-calling API at all**. That makes it immune to the parser failures below. It reaches models through LiteLLM and OpenRouter and is the reference harness for SWE-bench's bash-only leaderboard ([GitHub](https://github.com/SWE-agent/mini-swe-agent)). It has no TUI or hooks, so it fits Gas City's exec or subprocess runtime, not Gas Town's tmux polecats. **OpenHands CLI** (`--json` JSONL, always auto-approves in headless mode, LiteLLM) ([docs](https://docs.openhands.dev/openhands/usage/cli/headless)) and **Cline CLI 2.0** (`-y`/`--json`, Node 20+) ([blog](https://cline.bot/blog/introducing-cline-cli-2-0)) are viable exec-style workers, but they have rough edges. OpenHands mixes non-JSON lines into stdout and can hang on first run without settings. Cline's `--yolo` forces headless mode and breaks tmux launches ([issue #4944](https://github.com/OrchestratorInc/agent-orchestrator/issues/4944)). The rest are poor fits. **Factory Droid** is closed source, tests BYOK only against official Anthropic and OpenAI APIs, and has a reported ticket saying `droid exec` "doesn't support custom models" ([BYOK docs](https://docs.factory.ai/model-independence/byok), [issue #691](https://gh.r-mj.com/Factory-AI/factory/issues/691)). **Crush** is FSL-1.1 source-available, with no documented headless run flags ([rywalker](https://rywalker.com/research/crush)). **Aider**'s last official release was v0.86.2 in February 2026 ([PyPI](https://pypi.org/user/paul-gauthier/)). Kimi Code CLI's `kimi acp` is a plausible Gas City ACP worker for Kimi models, but it was not evaluated in depth.

## Most local-model failures happen in the serving stack, not the harness

All three primary candidates, plus Qwen Code, OpenHands and Cline, depend on the server turning model output into structured tool calls, and that layer has well-documented failures. On vLLM, the `qwen3_coder` parser sometimes leaves tool calls in plain content ([vLLM #22975](https://github.com/vllm-project/vllm/issues/22975), closed as not planned). Combining `--reasoning-parser qwen3` with `--tool-call-parser qwen3_coder` can **drop tool calls emitted inside `<think>`** ([vLLM #39056](https://github.com/vllm-project/vllm/issues/39056)). Community guidance favors `qwen3_xml` on current vLLM ([nrrso templates](https://huggingface.co/nrrso/Qwen3-Chat-Template-vLLM-Fixes)). llama.cpp needs `--jinja` and a build that includes the Qwen3-Coder XML parser from [PR #16755](https://github.com/ggml-org/llama.cpp/pull/16755). For gpt-oss, vLLM's Harmony parser can turn a stray header into a bogus tool call named `assistant<|channel|>analysis` ([vLLM #58825](https://github.com/vllm-project/vllm/issues/58825)), and chained calls can collapse into raw Harmony text. Some community chat templates that fix agent-loop aborts rely on vLLM-only Jinja filters and break on llama.cpp ([scchow templates](https://huggingface.co/scchow/Qwen-Fixed-Chat-Templates)). Ollama's default 4,096-token context is too small for any of these agents ([localaimaster](https://localaimaster.com/blog/goose-ollama-local-agent)). SGLang-specific parser issues were not researched and remain an open question.

The practical consequence is that **a supervisor watchdog matters more than harness choice.** It should catch tool calls that leak into text, and turns that end with neither a tool call nor completion, then re-nudge or restart the worker. The test suite for each stack should exercise multi-turn streaming tool calls, not single calls.

## Recommendation: Pi over RPC, OpenCode V2 as fallback, mini-swe-agent as control

**Primary worker: Pi 1.5.0 in `--mode rpc`, one process per worktree container.** A custom supervisor or Gas City runtime should drive RPC directly instead of the tmux TUI the stock presets use. That removes the 8-second readiness delay and gives steering, abort and cost polling. **First fallback: OpenCode 2.2.5** via `run --standalone --auto --format json` with explicit V2 permissions. It is the better choice wherever a built-in shell timeout and fail-closed headless permissions are worth more than Pi's provider tuning. **Second fallback: Goose 1.57.0** via `run --output-format stream-json`. Use it only after confirming that #12884 does not affect your codebase's languages. **Control and robustness fallback: mini-swe-agent**, for any model and server combination whose tool parser misbehaves. Use **Codex CLI** only on OpenRouter Responses routes or behind a tested proxy, and **Qwen Code** only if it beats Pi on Qwen models in your own bake-off.

**Bake-off plan.** Pick 30 to 50 representative beads from your own backlog, each with a test that verifies success. Run a matrix of {Pi, OpenCode V2, Goose, mini-swe-agent, plus Qwen Code if Qwen-centric, plus Codex via proxy if curious} × {two or three 32B to 70B models, such as a Qwen3-Coder variant, a GLM or DeepSeek model, and gpt-oss} × {vLLM, SGLang, llama.cpp, OpenRouter}. Use fixed version pins and three seeds. Measure pass rate on hidden tests, cost and tokens per solved task, wall-clock time, turns, edit-failure rate, and a separate counter for **serving-layer faults** (leaked or dropped tool calls, 400s). Also measure idle and peak RSS and cold start per worker, since no source has measured them for any of the three. Run 10 to 20 concurrent workers to surface memory growth and shared-service failures. Goose's in-repo Harbor tooling supports OpenRouter and offers a ready Terminal-Bench 2 harness ([Harbor](https://github.com/aaif-goose/goose/blob/main/evals/harbor/README.md)) for an external sanity check. Treat mini-swe-agent's score as the floor: a feature-rich harness that cannot beat it on a given stack is adding risk without adding value.

## Conclusion

The question has moved from which agent is smartest to which agent fails most legibly when unattended. With frontier models, harness differences are a few points (47% to 57% on the same TB2 run). With 32B to 70B models, the vendor's own Qwen data shows a minimal JSON harness beating a polished CLI by 10 points, and the dominant failures sit below the harness in parsers and templates. That favors workers that expose control and telemetry (Pi's RPC) and degrade predictably (OpenCode's auto-reject, mini-swe-agent's parser-free loop) over workers that offer more features. The second lesson is about churn. All three primary candidates broke integration contracts during 2026: Pi's package rename and schema validation changes, OpenCode's V1-to-V2 plugin and permission break, and Goose's server and tool replacement. Gas Town's own OpenCode preset is already a casualty. Version pinning, a canary lane and a per-stack conformance test therefore belong in the supervisor itself.
